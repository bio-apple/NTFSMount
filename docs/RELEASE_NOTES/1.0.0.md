# NTFSMount 1.0.0

Personal-use. Not notarized. Do not mirror or treat as a product until FUSE-T written permission and Apple notarization. See NOTICE.

Apple Silicon + macOS 13.0+ only. GitHub Latest points at this personal-use DMG (`/releases/latest/download/NTFSMount.dmg`). Writing or formatting an NTFS disk can cause data loss; back up first. FUSE-T `go-nfsv4` is not GPL.

Version-number reset of the current tree (`CFBundleShortVersionString` 1.0.0, `CFBundleVersion` 1). Includes the former 1.2.1 feature set plus untagged work after that ship.

## What's new

- Safer unmount: force unmount only after a busy-volume confirmation in the UI.
- Helper `repair-env` to clear leftover numbered mount points / orphan localhost NFS without force-unmount, ntfsfix, or clearing hiberfile.
- Disk status rows (mount mode, used space, encryption hint, journal).
- Auto-mount does not attempt writable mount on dirty / hibernated / corrupt volumes.
- Glanceable NTFS volume status on the menu-bar icon (hover card).
- Helper CDHash pinning (`allowed.cdhash`) and IPC v2.
- In-app environment diagnose window.
- Locales (English / Simplified Chinese / Traditional Chinese / Japanese).
- README download is GitHub Latest. In-app Sparkle stays off until notarized.
- About, Settings, and the menu-bar About item show the marketing version from Info.plist (`1.0.0`).
- CI runtime SHA256 check and generated release notes.

## Fixes

- Helper install on macOS without `/usr/bin/realpath`.
- Helper `CommandPath` resolution when installing the LaunchDaemon.
- Diagnose no longer treats leftover macFUSE noise as a blocking error.
- Unmount no longer force-pops busy volumes without confirmation.

## Breaking Changes

- `HELPER_VERSION` 9 → 10. Reinstall the mount helper after replacing the app.
- GitHub tags `v1.2.0` and `v1.2.1` were withdrawn; this tree is published as `v1.0.0`.

- Personal-use only (bundled FUSE-T). Do not mirror or sell.

## Helper: reinstall required?

- **Yes.** After replacing the app, use **Update mount helper**. Required even if writable mounts still appear to work.
- Why:
  - `HELPER_VERSION` 9 → 10 (`ntfs-rw-helper` SHA, `helper.stamp`, safer unmount, `repair-env`).
  - Users coming from 1.2.0 or earlier also pick up IPC v2 and CDHash pinning (`allowed.cdhash`).
- The app may fall back to IPC v1 if an old daemon returns a protocol error; that is not a substitute for reinstall.

## Old config compatibility

- **UserDefaults:** `com.bioapple.ntfsmount.*` keys are unchanged. First launch still migrates `local.ntfsmount.autoMountUserOff` and `local.ntfsmount.didShowCompatNotice` once (`didMigrate`).
- **Auto-mount:** `autoMountUserOff` is preserved. LaunchDaemon plist names are unchanged.
- **Helper stamp:** `/Library/Application Support/NTFSMount/helper.stamp` and `allowed.cdhash` must be rewritten by the helper installer (bundled SHA / CDHash changed). `lastHelperSHA` updates after a successful install.
- **Leftover sudoers:** `/etc/sudoers.d/ntfs-rw` and `/usr/local/sbin/ntfs-rw-helper` are treated as stale. Install / update / uninstall helper deletes them. Do not keep NOPASSWD leftovers.
